# HFT LOB SDK

A C++20 low-latency market-data and limit-order-book processing SDK with Python bindings, live exchange adapters, reproducible benchmarks, and production-oriented observability.

> [!NOTE]
> The transport/runtime layers are engineering infrastructure for integration and evaluation. Signal research, paper reproduction, and backtests are research diagnostics **not evidence of tradable alpha and not a complete live trading system**.

## Performance at a glance

Benchmarks below are generated by the repository's reproducible benchmark pipeline. The current checked-in run was measured on an Apple-silicon MacBook Air using a Release build with `-march=native` and Google Benchmark v1.9.1.

| Benchmark | Result |
| --- | ---: |
| RingBuffer vs `std::queue` + mutex at 1M events | **2.71x lower per-event latency** |
| RingBuffer at 1M events | **3.47 ns/event** |
| Cache-warm RingBuffer hand-off | **2.0 ns p50 / 3.2 ns p99** |
| SIMD Welford vs scalar | **2.01x** |
| Cross-thread Disruptor-style ring | **13.6M events/s** |
| Cross-thread ring vs queue | **1.18x throughput improvement** |
| Best real BTCUSDT volume-OBI R² | **0.00292 — no usable alpha demonstrated** |

![Queue vs lock-free RingBuffer latency](benchmarks/plots/queue_vs_ringbuffer.png)

The single-thread queue comparison isolates synchronization/allocation overhead rather than multi-core contention. Results are hardware- and compiler-dependent; re-run the suite on the target machine before making capacity claims.

## What this project demonstrates

- **C++20 low-latency transport** — cache-line-aligned ring buffers, SPSC queues, Disruptor-style fan-out, staged consumer dependencies, and cross-thread benchmarks.
- **Real-time market-data processing** — rolling count- and volume-based order-book imbalance, structural order filters, snapshots, regime tuples, and deterministic replay.
- **Live adapters** — Binance and Bybit perpetual-market ingestion with reconnect/backoff, sequence-gap tracking, and snapshot recovery.
- **C++ / Python interoperability** — installable C++ SDK plus pybind11 bindings for NumPy/Pandas workflows.
- **Operational runtime** — `hft_feed` with structured logging, Prometheus metrics, health endpoints, graceful shutdown, replay, and stdin ingestion.
- **Reproducible performance work** — Google Benchmark, stress/edge-case tests, soak tests, generated charts, and machine-readable benchmark artifacts.
- **Research tooling** — OBI signal evaluation, deterministic execution-cost backtests, paper-faithful diagnostics, Hawkes analysis, and pairs-trading experiments.

## Architecture

```text
market data
    |
    v
ingest adapters (file replay + Binance/Bybit live)
    |
    v
hft_feed runtime (config, structured logs, Prometheus, health)
    |
    v
SPSC queue / ring buffer
    |
    v
order tracker -> filter masks -> rolling count & volume windows
    |
    v
signal snapshots -> metrics / regime tuples
    |
    +--> C++ execution-cost backtest
    |
    +--> paper-faithful filters + regime/Hawkes diagnostics
    |
    +--> Python research/reporting layer
```

The latency-sensitive event path stays in C++; Python is used for research, analysis, and reporting.

## Quick start

### Python

```bash
python3 -m pip install .
hft-sdk data/sample_ticks.csv --scheme MTF --horizon 10 --signal volume
```

```python
import hft_sdk

result = hft_sdk.run_csv(
    "data/sample_ticks.csv",
    scheme="MTF",
    horizon=10,
)

print(result.metrics_dataframe())
print(result.backtest().total_return)
```

Optional extras:

```bash
python3 -m pip install ".[pandas]"
python3 -m pip install ".[live]"
```

### C++

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DHFT_BUILD_SHARED_SDK=ON \
  -DHFT_BUILD_PYTHON=ON
cmake --build build -j
cmake --install build --prefix /opt/hft
```

Consume from another CMake project:

```cmake
find_package(HftSdk REQUIRED)
target_link_libraries(your_target PRIVATE HftSdk::sdk)
```

Minimal usage:

```cpp
#include <hft/HftSdk.hpp>

hft::sdk::OBIFilterEngine engine;
engine.process(events);

auto snapshots = engine.snapshots();
auto metrics = engine.metrics();
```

## Runtime and observability

`hft_feed` is the long-running runtime for normalized market events:

```bash
hft_feed --config config/hft_feed.conf --replay data/sample_ticks.csv
curl -s http://127.0.0.1:9100/health
curl -s http://127.0.0.1:9100/metrics
```

It supports file replay, newline-delimited stdin ingestion, config files plus `HFT_*` environment overrides, structured JSON logs, Prometheus metrics, health/state reporting, sequence-gap tracking, and graceful SIGINT/SIGTERM shutdown.

Containerized runtime:

```bash
docker build -t hft-sdk:1.0.0 .
docker run --rm -i -p 127.0.0.1:9100:9100 \
  hft-sdk:1.0.0 --config /etc/hft/hft_feed.conf --stdin
```

## Live market data

Install live dependencies and connect to supported crypto perpetual feeds:

```bash
python3 -m pip install ".[live]"
python3 -m hft_sdk live --venue binance --symbol BTCUSDT --scheme MTF
python3 -m hft_sdk live --venue bybit --symbol BTCUSDT
```

The adapters reconnect with backoff and track depth-sequence continuity. Binance uses a snapshot bridge and resets signal history after a detected discontinuity and resnapshot.

The package can also fetch and normalize public Binance and crypto-lob-stream datasets for repeatable offline evaluation.

## Benchmark details

### Lock-free transport

At 1,000,000 events on the benchmark host:

| Transport | ns/event | Relative |
| --- | ---: | ---: |
| `std::queue` + mutex | 9.42 | 1.00x |
| RingBuffer | **3.47** | **2.71x** |

The RingBuffer is preallocated and reuses fixed-capacity storage. The baseline performs a locked push and pop for each event.

### Cache-warm hand-off

| Path | p50 | p90 | p99 |
| --- | ---: | ---: | ---: |
| Cache cold | 6.5 ns | 8.5 ns | 10.4 ns |
| Cache warm | **2.0 ns** | **2.0 ns** | **3.2 ns** |

![Cache-cold vs cache-warm RingBuffer latency](benchmarks/plots/latency_distribution.png)

The latency sampler amortises measurement over batches of 64 hand-offs because timer resolution is too coarse for reliable single-operation timing at this scale.

### Cross-thread producer / consumer

A separate benchmark measures actual hand-off between producer and consumer threads:

| Path | Median ns/event | p99 ns/event | Events/s |
| --- | ---: | ---: | ---: |
| `std::queue` + mutex + condition variable | 88.704 | 138.236 | 10,319,034 |
| Disruptor-style ring + busy spin | **75.227** | **92.563** | **13,635,948** |

![Cross-thread queue vs Disruptor-style ring](benchmarks/plots/lowlatency/threaded_queue_vs_ring.png)

The measured throughput improvement on this laptop run was **1.18x**. This benchmark includes thread creation/join overhead and is intentionally reported separately from the single-thread transport microbenchmark.

### Optimization experiments

Not every optimization wins. The benchmark suite retains negative results instead of tuning them away: some prefetching and SIMD variants are slower than compiler-optimized scalar code on this Apple-silicon host, while SIMD rolling-window work and Welford statistics show measurable gains.

![Selected low-latency microbenchmark results](benchmarks/plots/lowlatency/microbenchmarks.png)

## Verification

Run the main verification pipeline:

```bash
python3 -m pip install -r benchmarks/requirements.txt
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
./tools/run_pipeline.sh
```

The pipeline builds and tests the SDK, generates deterministic fixture data, evaluates the research path, runs the benchmark suite, and regenerates reports and charts.

Additional harnesses cover paper-faithful diagnostics, stress/edge cases, long-run replay, low-latency threaded transport, and pairs-trading experiments.
